# 从零到一：我的第一个全栈项目与踩坑日记

大家好，我是 AXunKK。今天，我在这里写下我的第一篇技术博客。

作为一个零基础自学编程的普通人，我没有耀眼的学历背景，也没有从事IT行业的父母可以给我提供资源和指导。但我始终相信：**代码是这个世界留给普通人最公平的武器**。只要肯折腾，键盘敲下的每一行代码，都在重塑自己的未来。

最近这段时间，我完整地经历了一次“从写代码到做项目，再到啃下大型开源项目”的蜕变。

## 🛠️ 我的第一个全栈项目：To-Do List

一开始，我只是学完了 Python 的基础语法，连网页是怎么跑起来的都不知道。但我决定不局限于“控制台打印九九乘法表”，我要做一个真正能用的东西。

于是，我从零开始，用 **Flask + SQLite + HTML/CSS** 搭建了一个待办清单（To-Do List）：
* 实现了完整的增删改查（CRUD）、撤销功能。
* 用原生的 JavaScript 实现了无刷新（AJAX）交互。
* 增加了状态筛选（全部/未完成/已完成）和截止日期筛选。
* 为了体验，我还自己写了 CSS 美化界面，并加入了自动填充日期等用户体验优化。

最后，我甚至用 `PyWebview` 和 `PyInstaller` 把它打包成了一个真正的 `.exe` 桌面软件！当双击图标，看到自己做的软件在独立的窗口中运行时，那种成就感是无与伦比的。

## 🔥 地狱级挑战：在 Windows 上跑通 Flask 大型项目

在拥有了一点实战经验后，我决定挑战 Miguel Grinberg 大神的开源项目 —— Flask 微型博客（Microblog）。这是一个带有完整应用工厂模式、蓝图和数据库迁移的工业级项目。

然而，真正的噩梦（也是最好的学习）才刚刚开始。

<img width="1289" height="1035" alt="image" src="https://github.com/user-attachments/assets/59736bd9-0741-47d0-84bf-e620df10a746" />

### 1. Python 版本的兼容性灾难
我电脑里安装了最新的 Python 3.14，导致安装项目依赖时，`psycopg2`、`multidict` 等库频繁报错：
`error: Microsoft Visual C++ 14.0 or greater is required.`
这是因为最新版的 Python 还没有提供这些库的预编译包，导致系统疯狂尝试从源码编译，最终崩溃。

### 2. 降级与虚拟环境
最终，我学会了降级安装 **Python 3.12**，并在终端里用 `py -3.12 -m venv venv` 强制重建了虚拟环境。彻底抛弃旧环境，这才解决了编译器的根本问题。

### 3. 果断“断舍离”与奇葩拼写错误
为了解决死循环的编译报错，我最终注释掉了 `requirements.txt` 里暂时不需要的依赖（如 `psycopg2-binary`、`multidict`），直接手动安装核心包。
期间还闹了一个笑话：我在 `requirements.txt` 里不小心多打了一个字母 `s`（`urllib3==2.1.0s`），导致 `pip install` 直接卡死报错，排查了半天才抓出这个拼写内鬼。

## 🚀 最终的成功与反思

当我解决完所有问题，在终端看到那句无比亲切的 `* Running on http://127.0.0.1:5000` 时，网页浏览器里跳出完整的博客页面，允许我注册、发帖……那一刻，所有试错的疲惫都值了。

<img width="950" height="376" alt="image" src="https://github.com/user-attachments/assets/d949ecb9-e7e0-43ed-8c50-019fe8664d1c" />

这几次经历让我深刻理解了：
1. **不要死磕，学会妥协**：遇到环境报错，绕过非核心依赖，先跑通主干流程才是硬道理。
2. **看懂报错是一种能力**：终端里的红字不可怕，一句一句往上找线索，总能抽丝剥茧。
3. **拥抱 AI 与文档**：自学不代表孤军奋战，遇到问题学会向社区和 AI 提问，是事半功倍的技能。
